# v0.3 主干收敛实施任务表

日期：2026-05-15  
版本目标：围绕“弱磁 + 连续控制 + 非线性磁链 LUT + 安全保护”收敛唯一工程主线。  
范围：`sim/`、`models/`、`tests/`、`experiments/`、`claude-review/`。

---

## 1. v0.3 目标定义

v0.3 不是继续新增实验，而是把现有主线实验真正收敛成统一控制输出链。

本阶段完成标志：

1. 控制 LUT 生成不再局限于单一 target torque；
2. 不可行原因能被统一识别、统计、回溯；
3. 温度 / 退磁安全边界进入主线控制搜索，而不是只停留在独立实验；
4. 非线性磁链 LUT 与主线控制输出完全对齐；
5. 模式切换连续性、边界与校验指标能够直接作为 G3 证据。

---

## 2. 任务 T1：控制 LUT 从单转矩点扩展到二维速度-转矩网格

### 2.1 目标

把 `run_control_lut_generator.py` 从“围绕单个 target torque 生成控制点”升级为“围绕速度轴 × 转矩轴生成真正的控制 LUT”。

### 2.2 涉及文件

- `sim/run_control_lut_generator.py:44`
- `sim/search.py:127`
- `sim/search.py:151`
- `models/control_lut_schema.json:150`
- `tests/test_control_lut_generator.py:24`

### 2.3 具体动作

1. 在 LUT 生成器中引入明确的 `torque_axis_nm`。  
2. 对每个 `(speed_rpm, torque_nm)` 生成控制点，而不是只使用 `params.torque_target_nm`。  
3. 补齐 `grid_definition` 中的 `torque_step_nm` 和二维语义。  
4. 让 `control_points` 数量与速度轴 × 转矩轴一致。

### 2.4 输入来源

- `models/motor_params.json`
- 现有 `speed_grid()` 逻辑
- 后续可扩展为 experiment 级配置

### 2.5 验收方式

- `models/control_lut.json` 中出现多点 `torque_axis_nm`；
- `control_points` 数量与二维网格匹配；
- `tests/test_control_lut_generator.py` 新增二维断言并通过；
- schema 与输出一致。

### 2.6 风险

- 现有模式判定逻辑是单目标点思路，二维化后边界检测复杂度提升；
- 需要防止 control point 数量暴增导致测试和输出过大。

## 3. 任务 T2：统一不可行原因口径

### 3.1 目标

把当前较粗的不可行判定，统一为主线可追溯的原因集。

### 3.2 涉及文件

- `sim/search.py:103`
- `sim/search.py:127`
- `sim/search.py:151`
- `sim/search.py:171`
- `sim/run_control_lut_generator.py:215`
- `sim/run_control_lut_generator.py:293`
- `models/control_lut_schema.json:346`
- `tests/test_control_lut_generator.py:55`

### 3.3 统一原因集

- `voltage_exceeded`
- `current_exceeded`
- `demagnetization_risk`
- `out_of_flux_lut_bounds`
- `search_not_converged`

### 3.4 具体动作

1. 在搜索链路中明确区分“无候选”“越电压”“越电流”“越 LUT 范围”“被安全边界拒绝”。  
2. 在 `ControlPoint` 输出中保留统一原因值。  
3. 在 `feasibility_map` 中做闭环统计。  
4. 保证线性 dq 与非线性 LUT 两条路径共用同一口径。

### 3.5 验收方式

- 所有不可行点都带有原因；
- `feasibility_map.infeasible_reasons` 统计与控制点数量闭合；
- 现有 schema 无冲突；
- 相关 pytest 通过。

### 3.6 风险

- 现有 `Candidate` 结构可能不直接承载原因，需要小范围接口扩展；
- 需要避免把“没有搜索到候选”误判成单一电压问题。

## 4. 任务 T3：把温度 / 退磁安全边界接入控制主干

### 4.1 目标

把 `exp_004` 中已验证的温度修正和退磁约束，接入 control LUT 生成主链。

### 4.2 涉及文件

- `sim/run_safety_boundary_experiment.py:53`
- `sim/run_control_lut_generator.py:44`
- `sim/search.py:127`
- `models/control_lut_schema.json:194`
- `tests/test_safety_boundary_experiment.py:9`
- `tests/test_control_lut_generator.py:75`

### 4.3 具体动作

1. 定义 control LUT 生成时可选的 thermal / demag 限制输入。  
2. 把 `DemagLimit` / `ThermalModel` 变成可复用依赖，而不是只在实验 runner 内部使用。  
3. 候选过滤时直接拒绝越过 `id_min(T)` 的点。  
4. 在 `mode_transitions.demagnetization_limit` 中输出边界信息。  
5. 在 metadata 或 model_source 中记录边界来源。

### 4.4 验收方式

- 高温/低母线时 LUT 可行域显著收缩；
- 输出中出现与退磁约束相关的边界或不可行统计；
- `tests/test_safety_boundary_experiment.py` 保持通过；
- 新增 control LUT 安全边界测试通过。

### 4.5 风险

- 当前 `exp_004` 使用的是简化折线 demag limit，接入主干时必须明确它仍是近似模型；
- 需要避免把实验性安全模型误表述为工程最终边界。

## 5. 任务 T4：把非线性磁链 LUT 完整对齐到主线控制输出

### 5.1 目标

让非线性磁链路径不只是单独 `exp_006` 跑通，而是成为 control LUT 主干的一等输入源。

### 5.2 涉及文件

- `sim/run_nonlinear_flux_lut_search_experiment.py:25`
- `sim/run_control_lut_generator.py:44`
- `sim/search.py:197`
- `models/flux_lut_schema.json:1`
- `models/control_lut_schema.json:59`
- `tests/test_nonlinear_flux_lut_search.py:85`
- `tests/test_control_lut_generator.py:14`

### 5.3 具体动作

1. 固化 `model_source.model_type=nonlinear_flux_lut` 的输出语义。  
2. 明确 LUT 裁剪导致的不可行区如何在 control LUT 中表达。  
3. 对齐 `exp_006` 输出和 `control_lut.json` 的口径。  
4. 让控制生成器在 LUT 模式下也能输出连续性指标和 feasibility map。  
5. 保证线性 dq 与 LUT 两路径除了模型来源不同，其余主干字段尽量一致。

### 5.4 验收方式

- `run_control_lut_generator.py` 在 nonlinear 模式下稳定输出；
- `flux_lut_ref`、LUT bounds 影响可追溯；
- 越界点标记为 `out_of_flux_lut_bounds`；
- `tests/test_nonlinear_flux_lut_search.py` 和 control LUT 相关测试全部通过。

### 5.5 风险

- 现有 LUT 搜索是 speed sweep 视角，control LUT 是发布视角，字段需要统一而非简单复制；
- 需要避免 schema 含义重叠或重复记录。

## 6. 任务 T5：补齐模式切换与连续性验证指标

### 6.1 目标

把当前较基础的模式分类和连续性检查，升级成可作为 G3 证据的验证模块。

### 6.2 涉及文件

- `sim/run_control_lut_generator.py:196`
- `sim/run_control_lut_generator.py:261`
- `sim/run_control_lut_generator.py:313`
- `models/control_lut_schema.json:194`
- `models/control_lut_schema.json:260`
- `tests/test_control_lut_generator.py:65`

### 6.3 具体动作

1. 细化 `MTPA/FW/MTPV` 边界定义逻辑。  
2. 输出边界点时补齐跳变量，如 `id_jump_a`、`iq_jump_a`、`torque_jump_nm`。  
3. 在 `validation` 中保留最大斜率、低电压裕度点、连续性通过/失败标记。  
4. 为二维 LUT 场景定义按速度切片或按转矩切片的连续性检查。

### 6.4 验收方式

- `mode_transitions` 不再只是空壳字段；
- 连续性失败能被测试捕获；
- `validation` 字段与 schema 完整一致；
- 可作为 `G3_model_simulation_and_controls` 的汇总证据。

### 6.5 风险

- 模式边界定义若过于经验化，会影响后续工程可信度；
- 需要注意不同 torque 轴切片下的连续性判断口径一致。

## 9. 建议执行顺序

### 第 1 步

先做 **T2 不可行原因统一**，因为它会影响后面安全边界和 LUT 越界表达。

### 第 2 步

做 **T3 安全边界接入主干**，先把 exp_004 的成果从独立实验变成主干能力。

### 第 3 步

做 **T4 非线性磁链对齐主干**，保证 linear / nonlinear 两路径共享同一输出口径。

### 第 4 步

做 **T1 二维控制 LUT 扩展**，把主干从单目标点升级为真正发布型查表结构。

### 第 5 步

最后做 **T5 模式切换和连续性强化**，沉淀为 G3 证据。

## 10. 最终判断

v0.3 最关键的不是“再增加一个实验”，而是把已经存在的：

- 线性 dq 主线，
- 非线性 LUT 主线，
- 安全边界主线，
- 控制 LUT 主线，

真正合并为一条统一的工程控制输出链。

如果这五个任务完成，项目就会从“实验拼盘”明显前进一步，进入“可持续工程主干”状态。
