# v0.3 Control LUT 主线闭环记录

日期：2026-05-16  
范围：`sim/run_control_lut_generator.py`、`models/control_lut_schema.json`、`models/control_lut.json`、`tests/test_control_lut_generator.py`。

---

## 1. 闭环结论

v0.3 control LUT 主线已经从“单目标转矩、线性 dq speed sweep 输出”收敛为可承载 G3 模型 / 仿真 / 控制证据的统一控制查表链路。

本轮闭环后，control LUT 具备：

1. 速度 × 转矩二维网格输出能力；
2. 统一不可行原因口径与 feasibility map 统计闭合；
3. 温度修正与退磁限制可选接入；
4. nonlinear flux LUT 模式主线输出；
5. 按 torque 切片的模式转换、连续性与跳变验证指标。

该闭环仍属于参数化仿真主线，不等同于工程实测验证；所有输出仍应保留 v0 模型限制语义。

## 2. T1：二维速度-转矩 control LUT

### 2.1 已落地能力

`run()` 新增可选输入：

- `torque_axis_nm: list[float] | None`
- `torque_step_nm: float | None`

默认行为保持兼容：

- 未传入 `torque_axis_nm` 时，使用 `[params.torque_target_nm]`；
- 默认不自动生成大范围转矩扫描，避免输出体积和测试时间失控。

显式传入 torque axis 时，生成器对每个 `(speed_rpm, torque_nm)` 执行搜索并输出一个 control point。

### 2.2 输出契约

`grid_definition` 现在表达真实二维网格：

- `speed_axis_rpm`
- `torque_axis_nm`
- `speed_step_rpm`
- `torque_step_nm`

其中：

- 单点 torque axis 的 `torque_step_nm = 0.0`；
- 均匀 torque axis 的 `torque_step_nm = step`；
- 非均匀 torque axis 的 `torque_step_nm = null`。

`models/control_lut_schema.json` 已允许 `torque_step_nm` 为 `number | null`，并说明非均匀转矩轴时为 `null`。

### 2.3 校验

新增测试覆盖：

- 默认单 torque 兼容；
- 显式 torque axis；
- control point 数量与 `speed_axis × torque_axis` 闭合；
- `(speed_rpm, torque_nm)` 笛卡尔积完整覆盖；
- 非均匀 torque axis；
- 非法、非有限 torque axis / torque step 拒绝。

## 3. T2：不可行原因统一

### 3.1 已落地原因集

control LUT 不可行原因统一为：

- `voltage_exceeded`
- `current_exceeded`
- `demagnetization_risk`
- `out_of_flux_lut_bounds`
- `search_not_converged`

### 3.2 搜索层处理

本轮没有扩展 `Candidate` 公共结构，而是在 control LUT 生成层实现局部原因推断：

- candidate 电流裕度为负：`current_exceeded`；
- candidate 电压裕度为负：`voltage_exceeded`；
- nonlinear LUT 全部越界：`out_of_flux_lut_bounds`；
- demag 限制拒绝目标点：`demagnetization_risk`；
- 其他无候选：`search_not_converged`。

该选择符合 v0.3“小步主干增强”策略，避免过早引入全局 `SearchResult` 抽象。

### 3.3 统计闭合

`feasibility_map.infeasible_reasons` 已补齐全部原因，并通过测试验证：

```text
sum(infeasible_reasons.values()) == len([cp for cp in control_points if not cp["feasible"]])
```

## 4. T3：温度 / 退磁安全边界接入

### 4.1 已落地输入

`run()` 支持可选：

- `temperature_c`
- `thermal_model`
- `demag_limit`

当传入 `temperature_c` 时，生成器通过 `apply_temperature()` 修正电机参数。  
当传入 `demag_limit` 时，搜索过程过滤 `id_a < id_min_allowed(params.temperature_c)` 的候选点。

### 4.2 输出记录

退磁限制相关输出包括：

- `metadata.demag_limit`
- `feasibility_map.infeasible_reasons.demagnetization_risk`
- `mode_transitions.demagnetization_limit`

### 4.3 模型限制

当前 `DemagLimit` 仍是简化折线边界，用于主线控制搜索接入验证；它不是最终工程退磁边界。

## 5. T4：nonlinear flux LUT 对齐主线

### 5.1 已落地能力

`run(model_type="nonlinear_flux_lut", lut_path=...)` 可生成与线性 dq 同构的 control LUT 输出。

`model_source` 记录：

- `model_type = nonlinear_flux_lut`
- `flux_lut_ref`
- `linear_dq_ref = null`
- `experiment_ref = experiments/exp_006_nonlinear_flux_lut/`

### 5.2 路径策略

`lut_path` 必须解析到项目根目录内。外部绝对路径会抛出清晰 `ValueError`，避免读取外部文件后生成不可追溯的相对引用。

### 5.3 不可行原因

nonlinear 模式下，LUT bounds 与搜索不可行原因共用 T2 原因口径。测试覆盖了 in-bounds failure 不会被误标为 `out_of_flux_lut_bounds`。

## 6. T5：模式切换与连续性验证

### 6.1 transition 输出增强

`mode_transitions` 中的边界点现在记录：

- `id_jump_a`
- `iq_jump_a`
- `torque_jump_nm`

control point 新增：

- `actual_torque_nm`

`torque_jump_nm` 优先基于 `actual_torque_nm` 计算；当实际转矩缺失或为 `null` 时，回退到目标 `torque_nm`。

### 6.2 多 torque 语义

二维 LUT 下，transition、连续性和最大斜率必须按固定 `torque_nm` 切片沿速度轴计算。

本轮已修正：

- `_detect_mode_transitions()` 按 torque slice 检测；
- `_check_mode_continuity()` 基于 torque slice 最大 id slope；
- `_max_id_slope()` / `_max_iq_slope()` 按 torque slice 计算。

这避免了扁平 control point 列表中跨 torque 点误判模式切换或电流跳变。

### 6.3 validation 输出

`validation.torque_discontinuity_at_transitions_nm` 不再硬编码为 `0.0`，而是由 `mode_transitions` 中的实际跳变量聚合得到。

## 8. 当前已知限制

1. 默认输出仍是单 torque axis，用于保持运行时间和产物体积可控；完整 torque sweep 应由实验配置显式传入。
2. `tests/test_control_lut_generator.py` 仍是偏集成测试，完整运行时间较高；后续 v0.4 可拆分轴解析、transition helper、搜索主链测试。
3. 模式分类仍基于 voltage margin 阈值，属于 v0 控制策略近似；后续需要基于 FEA / 标定数据重新定义边界。
4. nonlinear flux LUT 当前使用样例 LUT，不能代表真实磁饱和地图。
5. 退磁限制仍是简化 `id_min(T)` 模型，不是最终硬件安全边界。
6. control LUT schema 还没有引入 requirement trace / boundary source 字段，v0.4 可补齐。

---

## 9. v0.4 建议入口

建议下一阶段优先推进：

1. 将 control LUT generator 的轴解析、搜索、transition validation 拆成更小模块；
2. 引入 `SearchResult` 或等价结果对象，减少 reason 推断散落；
3. 用实验配置文件驱动 torque axis / safety boundary，而不是仅通过函数参数；
4. 增加 schema validation 测试，确保 `models/control_lut.json` 始终符合 `models/control_lut_schema.json`；
5. 把 nonlinear flux LUT 从 sample 扩展到 FEA-derived LUT 输入链路。
