## 2. T2：不可行原因统一

### 2.1 目标

让 control LUT 中每个不可行点都有可解释原因，并让 feasibility map 与 control points 统计闭合。

### 2.2 推荐代码设计

#### 方案 A：扩展 `Candidate`

在 `sim/search.py:65` 的 `Candidate` 增加：

- `infeasibility_reason: str | None`

`make_candidate()` 根据边界判定：

- current 超限且 voltage 未超限：`current_exceeded`
- voltage 超限且 current 未超限：`voltage_exceeded`
- 两者都超限：优先 `current_exceeded` 或增加组合原因
- feasible：`None`

优点：原因随候选点传播，control LUT 可直接读取。  
缺点：会影响所有构造 `Candidate` 的测试和调用点。

#### 方案 B：不改 `Candidate`，在 control LUT 层推断

在 `run_control_lut_generator.py` 中新增 helper：

- `_candidate_infeasibility_reason(candidate: Candidate | None, fallback_reason: str) -> str | None`

根据 `candidate.current_margin_a`、`candidate.voltage_margin_v` 推断原因。

优点：改动较小。  
缺点：`None` 的真实原因仍需上层显式传入。

### 2.3 推荐选择

建议先采用 **方案 B**，因为 v0.3 的目标是主干收敛，不宜一次性扩散 `Candidate` 接口。

后续若要把搜索结果对象标准化，可在 v0.4 再引入 `SearchResult` 类型。

### 2.4 具体变更清单

1. 在 `run_control_lut_generator.py` 新增原因推断 helper。  
2. `_candidate_to_control_point()` 增加 `infeasibility_reason` 参数或 fallback 参数。  
3. 当搜索返回 None 时：
   - LUT 网格为空：`out_of_flux_lut_bounds`
   - 安全边界拒绝：`demagnetization_risk`
   - 搜索未达到目标 torque：`search_not_converged`
4. `_build_feasibility_map()` 的原因字典补齐 schema 中全部原因。  
5. tests 补齐统计闭合断言。

### 2.5 验收标准

- 所有不可行 control point 的 reason 非空；
- reason 值属于 schema 枚举；
- `sum(feasibility_map.infeasible_reasons.values()) == total_points - feasible_points`；
- nonlinear LUT 越界可以被标记为 `out_of_flux_lut_bounds`；
- current/voltage 超限不再全部写死为 `voltage_exceeded`。

## 3. T3：温度 / 退磁安全边界接入主干

### 3.1 目标

让 `exp_004` 中的安全约束成为 control LUT 生成时的可选主干能力。

### 3.2 推荐代码设计

新增一个轻量配置对象或参数组，不急于引入复杂框架：

- `temperature_c: float | None = None`
- `demag_limit: DemagLimit | None = None`
- `thermal_model: ThermalModel | None = None`

在 `run_control_lut_generator.run()` 中：

1. 读取基础 params；
2. 如果传入 temperature / thermal model，则用 `apply_temperature()` 得到新 params；
3. 如果传入 demag limit，则搜索时过滤 `id_a < id_min_allowed(params.temperature_c)`；
4. 输出 metadata / model_source / operating_limits 中记录安全边界来源。

### 3.3 搜索接入方式

短期推荐在 control LUT generator 内新增安全搜索 helper，而不是复用 `find_min_current_for_torque_with_safety()` 原样逻辑，原因：

- 后续需要同时支持 flux_lut；
- 当前 safety helper 只支持线性 `make_candidate()`；
- control LUT 还需要不可行原因和边界记录。

建议新增内部 helper：

- `_find_min_current_for_torque_with_optional_safety(params, omega_e, target_torque_nm, grid, flux_lut, demag_limit)`

逻辑：

1. 对 grid 做 LUT 裁剪；
2. 遍历电流点；
3. 先检查 demag limit；
4. 再 `make_candidate()`；
5. 选择最小电流候选；
6. 如果没有结果，返回 candidate=None + reason。

### 3.4 输出字段建议

在 control LUT 中补充或利用已有字段：

- `operating_limits.temperature_c`
- `mode_transitions.demagnetization_limit`
- `feasibility_map.infeasible_reasons.demagnetization_risk`
- `metadata.notes`
- `model_source.search_config` 可增加 safety constraint 说明

如 schema 不允许新增字段，则优先放入已有 `metadata.notes` 或 schema 允许的对象内；不要破坏现有 schema。

### 3.5 验收标准

- 高温 demag limit 下，control LUT 中不存在 `id_a < id_min_allowed` 的可行点；
- 被 demag limit 拒绝导致不可达的点计入 `demagnetization_risk`；
- `mode_transitions.demagnetization_limit` 不再永远为空；
- `tests/test_safety_boundary_experiment.py` 继续通过；
- `tests/test_control_lut_generator.py` 增加 safety 模式测试并通过。
